# VOXGATE research results dashboard

This update adds a **read-only local research report** at `http://127.0.0.1:8000/results/`.

It reads the files generated by `python audit_spoken_action_results.py`:

- `~/Desktop/voxgate-spoken-action-audit/audit_summary.json`
- `~/Desktop/voxgate-spoken-action-audit/policy_by_group.csv`

No data is uploaded; no model, audio file, or external tool is called. The dashboard *does not* infer that any symbolic action is safe or authorized.

## Setup

1. Unzip the update at `~/Desktop/voxgate`.
2. `python install_results_dashboard.py` (adds a URL route; backs up the previous URL file).
3. `python -m unittest core.test_results_dashboard -q`
4. `python manage.py test core.test_results_dashboard_django -v 1`
5. If needed, `python audit_spoken_action_results.py` to regenerate the local audit files.
6. Open `/results/` while the Django server is running.

If Django does not recognize the new route, restart the development server in Terminal 1.

The page is restricted to `DEBUG=True` requests from `127.0.0.1` or `::1`. This is a local-only prototype, not an authentication system or production deployment.

## Interpretation

The model’s action proposals are fictional action-catalog strings, not executed tasks. "Held" is a request for review. The correct-completion count and the wrong-proposal count should **both** be reported; a stricter gate can lower exposed errors simply by withholding more requests. Two spoken rates from the same prompt are repeated observations. These 24 researcher-constructed cases do not establish safety performance or model perception of acoustic authority.

The results view does not replace the full CSV reports, documented stimuli, labeling methods, or independently collected evaluation data required for publication.
